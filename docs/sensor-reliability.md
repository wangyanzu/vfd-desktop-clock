# AHT10 可靠性与实机排障

当前实机曾持续返回 `18 00 00 00 00 00`：校准标志存在，但测量部分全零，解码为 -50°C、0%RH。不能将这样的空帧作为室内数据，也不能仅凭地址能应答就认定传感器正常。

## 软件恢复

- 冷启动先等 100ms，发送软复位 `BA`，等 40ms 后检查状态。已校准的正常传感器不重复加载工厂系数；未校准或持续空帧 / 越界时才发送 `E1 08 00`，至少等待 350ms，并在有限时间内复查状态。
- 单次转换发送 `AC 33 00` 后至少等 120ms，先检查忙状态，再读取六字节数据。短读、NACK、忙或空帧不立即导致长时间离线；在约 500ms 窗口内短重试，最多重新触发 3 次转换。
- 连续失败后按 2 / 4 / 8 / 16 / 30 秒退避。先软复位，连续 3 个失败周期后尝试总线清除和重建。成功采样后清零连续失败计数，总样本 / 故障 / 恢复尝试计数保留。
- I²C 降为 50kHz，事务超时 20ms。总线清除最多 9 个时钟脉冲，使用开漏方式，只拉低或释放，绝不强推高电平；时钟释放等待有上限。总线不能释放时退出并退避，不死循环。
- 初次 I²C 初始化失败也进入自动恢复，不永久禁用采样。读取缓冲区长度不足时拒绝数据，避免把 `Wire.read()` 的 -1 当成真实字节。
- 每次状态机 tick 最多执行一次有界总线操作；不使用长 delay 等待传感器，不复位整个 ESP32 来恢复 AHT10，不影响 60 秒调暗 / 30 分钟休眠策略。
- 休眠唤醒保留最后真实读数，但先标为非新鲜，再重新初始化和采样。瞬时重试不会删除上次真实数值；最终失败时标记不可用 / 旧数据，从未成功时显示占位符。

## 诊断

串口 `t` 不再产生额外 I²C 探测，只输出缓存和引脚电平：

- `bus_ready`、`last_write`、`short_reads`：总线初始化、最近写入结果及短读次数；`last_write=0` 仅表示上次写入应答，不是当前在线探测。
- `samples / failures / consecutive / io_errors / empty_frames / resets / bus_recoveries`：真实采样、失败及恢复尝试计数。
- `raw`：最后完整测量帧，不将诊断帧或无效帧发布为温湿度。
- `SYSTEM: reset_reason`：ESP32 重启原因；`POWER: request=...` 区分按钮、串口或自动计时触发的电源操作。用于进一步定位无人工操作时的计时重置。

网页显示错误原因、连续失败和恢复尝试次数。`sensor.error` 的编号为：0 无错误、1 写入、2 状态读取、3 校准、4 忙超时、5 测量读取、6 空帧、7 越界、8 总线恢复失败。最近真实读数仍可显示，过期 / 失败必须标记。

## 模块与硬件

用户当前接线为 3.3V、约 10cm。成品模块可能自带 SDA/SCL 上拉和去耦，不能把“未外接电阻”等同于“没有上拉”；不要盲目并联电阻。是否需要补充应以模块原理图、电阻测量或示波器波形为准。

分级恢复不能修复传感器损坏、供电波动或实际接线故障。若重建总线、复位及重载校准后仍持续全零，需要用模块完全断电重上电、与 VFD 分离供电测试或替换模块来进一步定位，不应继续放宽数据校验或生成模拟值。

## 验证

`sh scripts/test.sh` 的 `aht10_test.cpp` 用故障注入覆盖冷启动、校准、唤醒、NACK / 短读恢复、持续忙 / 空帧 / 越界、断开后重连、分级恢复及计时回绕，同时检查每 tick 的总线操作数。`web_sensor_test.cjs` 验证错误原因、计数和最近真实值显示。软件测试不能代替实机长时间采样验证。
