# MQTT 消息接收与确认

当前支持接收 UTF-8 纯文本，将中文转换为屏幕 GB2312 字格，并在第二行显示。默认不连接 MQTT，也不沿用原参考代码的账号。MQTT 可以通过本地管理网页配置并保存，无需重新编译。

## 网页配置

打开本地管理页，在“消息连接”中填写服务器、端口、主题和认证信息，启用后点击“保存消息设置”。MQTT 使用独立的 NVS 记录（版本 1、336 字节、CRC32），不改变已有 Wi-Fi、时间和亮度配置。设备存储不可用或校验失败时不会发布新配置；损坏的已存记录会在启动时禁用 MQTT，不会自动恢复编译时凭据。

ClientID 与认证密码只显示“是否已保存”，不返回原值；每项均提供保留、替换和清除。巴法云私钥属于凭据，填入 ClientID。更换服务器、端口或 TLS 选项时，已有凭据必须重新填写或明确清除；单独修改主题可保留凭据。禁用 MQTT 会断开连接但保留所填配置，需清除凭据时明确选择“清除”。

保存成功后，独立连接任务关闭旧连接、重新订阅；正在等待连接或 TLS 时，新设置会在该次等待结束后应用。旧连接尚在交接缓冲内的消息会丢弃，已进入收件箱的待确认消息继续保留。保存成功表示设置已持久化，实际连接成功以状态反馈为准。

### 可选编译默认值

复制 `include/local_config.example.h` 为已忽略的 `include/local_config.h`，填写：

```cpp
#define CLOCK_MQTT_CLIENT_ID "你的客户端标识"
#define CLOCK_MQTT_TOPIC "你的消息主题"
#define CLOCK_MQTT_HOST "bemfa.com"
#define CLOCK_MQTT_TLS 1
#define CLOCK_MQTT_PORT 9503
#define CLOCK_MQTT_USERNAME ""
#define CLOCK_MQTT_PASSWORD ""
```

仅在未保存过 MQTT 网页配置时使用这些默认值；`CLIENT_ID` 和 `TOPIC` 都非空才默认启用。网页保存值始终优先，包括明确关闭的状态。主题是一个精确主题，不接受 `+` / `#` 通配符；客户端标识、主题、用户名、密码各最多 64 字节。编译配置会进入固件，不要分发包含个人凭据的固件。

根据 [巴法云 MQTT 官方说明](https://cloud.bemfa.com/docs/src/mqtt.html)，服务器为 `bemfa.com`，TLS 端口 9503、明文端口 9501；私钥可作为 ClientID，用户名与密码可留空。也支持按官方规则使用 AppID / SecretKey。不要把文档示例或他人的密钥用于设备。其他服务器需提供相应的标识、认证信息及由内置公共 CA 信任的证书。

默认 TLS 校验证书，等待有效校时时间后才连接；验证失败会重试，不会降级为明文。只有在网页明确选择明文 TCP 并填写对应端口，或将编译默认值 `CLOCK_MQTT_TLS` 设为 0 时，才使用明文。订阅 QoS 1，使用干净会话，重试间隔为 1 / 2 / 4 / 8 秒，逐步增长到 60 秒。依赖固定为 [256dpi/arduino-mqtt 2.5.3](https://github.com/256dpi/arduino-mqtt)。

## 显示与确认

- 发布内容为 UTF-8 纯文本，例如 `记得喝水，下午三点开会`，不是 JSON。最多 256 字节、128 个字格；超限、无效 UTF-8、全空白及协议控制字符会拒绝，不截断。换行和制表符转为空格；GB2312 不支持的字符（如大部分 emoji）显示为一个 `?`。
- 内存中最多保留 8 条未确认消息，按到达顺序显示。队列满时拒收新消息；与当前队列某条原始文本完全一致的消息合并计数。接收任务另有 4 条交接缓冲，突发超量也可能被拒收。
- 第一行右侧 `M1` 至 `M8` 表示待确认数量，末列保留离线标记。第二行最多显示 20 个字格，长消息首尾停留、逐格循环滚动；不自动确认，也不自动轮换到下一条。
- 显示睡眠及配网热点开放期间缓存消息。退出配网并处于唤醒状态后开始显示；目前尚未接入人体传感器，唤醒状态不代表判断到有人。
- 串口发送小写 `a`，或在管理网页点击“确认屏幕当前消息”，可确认当前一条。只接受已经完成入场并排空 UART 的对应页面；串口忙时请求可等待最多 5 秒。确认后显示 `MESSAGE CONFIRMED`，随后显示下一条或恢复原轮播页；该页重新获得完整停留时间。人工模式下按钮短按用于关屏休眠及唤醒，不确认消息；休眠关闭网络，暂停 MQTT 接收，内存消息保留。默认按钮为 GPIO3 接 GND。
- 网页显示连接状态、数量、配置及确认入口，不返回消息正文、ClientID 或认证密码。确认请求携带消息 ID 和 CSRF 令牌，过期 ID 不会误清下一条。HTTP 202 表示已接受处理请求，以设备反馈和刷新后的数量为准，不代表已经清除。

确认仅删除本机队列条目，不向发送方发布回执，不删除服务器 retained 消息。QoS 1 可能重复投递，去重仅作用于当前待确认队列；确认后再次收到相同内容仍会新增。队列和计数保存在 RAM，重启后丢失；干净会话不保证设备离线期间的消息补发。

## 验证边界

主机测试覆盖完整 GB2312 映射、非法输入、队列满、重复消息、滚动、计时回绕及旧 ID 确认；新增 MQTT 记录逐字节损坏、最大字段边界、凭据隔离及事务校验。网页使用 API fixture 验证确认、配置保存、凭据操作、重复提交和失败保留输入，轮询不会覆盖正在编辑的配置。独立接收任务避免在显示循环中等待 DNS / TCP / TLS，任务只通过固定容量队列交付正文，由主循环独占消息状态。

普通 UART、原生 USB 及虚构凭据的 MQTT 启用环境均已编译通过；尚未烧录或接入真实服务器。需在实物上检查 TLS 握手时的剩余堆内存、断网恢复、突发接收、中文显示效果与确认手感。不要烧录仅供编译检查的 `esp32c3-mqtt-check` 环境。
