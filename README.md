# VFD 桌面时钟

基于合宙 LuatOS CORE-ESP32-C3、M202MD28AA 20×2 VFD 和 AHT10 的桌面时钟。支持网页配网与管理、室内外温度显示、心知天气、MQTT 分级消息、GPIO3 确认及轻睡眠。

当前固件已在串口环境编译、烧录并通过写入校验；消息解析、队列、计时和网页交互已有自动测试。最近实机监测中天气接口正常、无异常重启，但 **AHT10 仍出现 I²C 写入失败，室内温湿度可靠性尚未验收通过**。固件保留自动重试与总线恢复，不能将这些机制视为传感器已经稳定。

## 显示与轮播

第一行固定显示年月、时分秒和星期，例如：

```text
2026-10 14:32:10 WED
 IN:24.6C RH:51.2%
```

- 时间数字直接更新；只对换页、消息入场、开机、休眠和唤醒使用动画。
- 室内传感器数据统一使用 `IN:`，室外天气接口数据使用 `OUT:`。可并列显示 `IN:25.6 OUT:18.0C`，不计算温差。
- 网页可选择室内温湿度、独立温度、独立湿度、室外天气、室内外对比，统一停留时间可设 5–120 秒；只选一项时固定显示。独立日期星期轮播页已取消，旧配置自动移除这一项。
- 普通轮播在消息、配网或睡眠期间暂停，恢复后获得完整停留时间。阅读计时从入场结束且 UART 排空后开始。
- 内容默认居中，每 5 分钟移动一格，在中心左右各 2 格内往返；偏移受剩余空白限制，不裁切文字。第一行占满 20 格，因此不偏移。这用于分散固定显示的负担，不保证消除烧屏。
- 首次联网取得 IP 后，第一行显示 IP、第二行显示管理密码 `KEY:xxxxxxxx`，居中停留 4 秒后返回普通页面。
- 没有有效时间时显示校时或离线状态，不显示 1970 年日期；没有有效读数时显示占位符。过期读数保留并标记 `*`，时间前的 `!` 表示 Wi-Fi 离线。

屏幕使用 9600 baud、8N1 的改装 UART 接口，按完整字格处理 ASCII 和 GB2312 中文，帧率上限约 10fps。默认动画为终端推入、消息逐字展开、唤醒中心展开和休眠收拢。可查看 [动画预览](docs/animation-preview.html) 与 [协议和动画设计](docs/display-animation-design.md)。

## MQTT 消息

发布 JSON：

```json
{"l":1,"msg":"记得喝水"}
```

| `l` | 级别 | 显示规则 |
| --- | --- | --- |
| 1 | 普通 | 显示 15 秒，播放 3 遍后自动清除 |
| 2 | 重要 | 显示 60 秒，播放 12 遍后自动清除 |
| 3 | 严重 | 持续循环，直到 GPIO3 或网页确认 |

每遍 5 秒。长消息开头停留 1 秒、在 3 秒内滚动到末尾、末尾停留 1 秒，速度按长度调整；短消息固定显示相应时长。入场动画不计时，配网或睡眠期间暂停，恢复后继续累计显示时间。兼容旧的 UTF-8 纯文本，按普通消息处理。屏幕只显示 `msg` 正文，网页标明当前级别。

### 长度与队列

- 正文同时受 **256 个 UTF-8 字节、128 个显示字格**限制：纯英文通常最多 128 个字符，常用纯中文最多约 85 个汉字。屏幕每行显示 20 个字格，长文本滚动，不截断超限消息。
- 整个 MQTT 负载最多 1024 字节，包括 JSON 字段和转义字符。拒绝非法级别、重复或未知字段、空白正文、无效 UTF-8、嵌入 NUL 及协议控制字符；换行和制表符转为空格。不支持的字形显示为 `?`。
- 显示队列最多 8 条，包含当前消息；MQTT 任务另有 4 条临时缓冲。两处均按级别和正文合并重复消息，JSON 字段顺序或转义形式不同不影响去重。
- 队列满时，先淘汰最低级别、且不高于新消息级别的旧消息；同级别先淘汰最早到达的一条。新消息比现有消息都低级时拒收。
- 严重消息不自动淘汰；全满为严重消息时拒收新消息。保留的条目仍按到达顺序显示，**不会按级别抢占或重新排序**。
- 网页分别显示待确认数量、拒收、淘汰和重复合并计数。队列中存在严重消息时暂缓自动休眠；确认严重消息后重新开始省电计时。

短按 GPIO3 优先确认消息；也可在管理页点击“确认屏幕当前消息”，或通过串口发送 `a`。仅确认已经完成入场并排空 UART 的消息，旧消息 ID 不会误清下一条。手动确认后显示 1 秒反馈；自动清除则直接进入下一条或恢复普通页面。

MQTT 默认关闭，管理页可配置巴法云或其他兼容服务器、端口、TLS、主题和凭据。TLS 保持证书验证，校时后连接，不自动降级为明文。确认仅删除本机队列，不发送业务回执、不删除服务器 retained 消息；队列、播放进度和计数都只在 RAM 中，断电或重启后丢失。详见 [消息接入说明](docs/mqtt-messages.md)。

## 按钮与省电

GPIO3 与 GND 之间接瞬时按钮，使用内部上拉：

| 操作 | 行为 |
| --- | --- |
| 亮屏时短按，有消息 | 确认当前消息，入场期间等待页面稳定后处理 |
| 亮屏时短按，无消息 | 关屏、断网并进入轻睡眠 |
| 睡眠时按下 | 唤醒并恢复联网；必须松开后再按才能确认消息或休眠 |
| 长按 3 秒 | 开放配网热点 |

上电或唤醒后先以 100% 高亮显示，60 秒后降为网页设置的常态亮度，默认 50%，可选 25% / 50% / 75%。自动休眠默认为 **1 小时**，管理页可选：

- 15 分钟、30 分钟。
- 1、2、3、4、5、6、7、8、9 小时。
- 永不自动休眠；仍可通过 GPIO3 手动休眠。

计时从上电或唤醒开始，网页轮询、普通消息和天气更新不延长亮屏时间。修改休眠时间沿用本次亮屏计时，缩短至已经超过的时长会触发休眠；严重消息按上一节规则暂缓自动休眠。

休眠前先完成动画并排空 VFD UART，等待 MQTT 和天气任务暂停，再关闭 Wi-Fi，进入 GPIO 唤醒的轻睡眠。准备最长等待 15 秒，超时或失败恢复亮屏并重新计时。睡眠期间网页不可访问，不接收 MQTT、不请求天气、不采样温湿度；内存与时钟保留。固件只发送 VFD 显示电源关闭命令，不切断屏幕外部供电，实际功耗仍需测量。

## 天气与温湿度

心知天气 V3 实况接口通过 HTTPS 和公私钥签名请求，默认每 15 分钟更新，可设 5–60 分钟。先完成校时，再进行签名；私钥不进入天气请求 URL。网页可配置城市、拼音、城市 ID 或 `纬度:经度`，名称匹配失败时可改用坐标。接口可能返回所属城市名称，不代表坐标处独立测站的读数。

接口失败时显示 HTTP 状态和经过校验的心知错误码，例如 `AP010010` 表示找不到地点。保留上次有效天气，超过 90 分钟标为过期；接口未提供湿度时明确显示缺失，不生成模拟数据。见 [天气设置与诊断](docs/weather.md)。

AHT10 每 5 秒采样，使用 50kHz I²C 和 20ms 单次事务超时。冷启动与唤醒后初始化，转换期间短重试，持续故障按 2 / 4 / 8 / 16 / 30 秒退避，必要时软复位、重载校准和恢复总线。网页显示错误与失败、恢复计数；串口 `t` 只读缓存，不插入额外探测事务。详见 [传感器恢复与排障](docs/sensor-reliability.md)。

## 网页配网与本地存储

1. 无网络配置时，连接设备热点 `W4VFD-Clock-xxxx`，后缀为 MAC 地址后四位。
2. 热点密码与管理密码均为屏幕显示的 8 位数字 `KEY`，可包含前导零。启动串口日志也会输出该密钥，家庭 Wi-Fi 密码不输出。
3. 打开 `http://192.168.4.1`，用户名为 `admin`，密码为该 `KEY`；当前没有自动弹出的 captive portal。
4. 保存家庭 Wi-Fi 后，打开屏幕显示的设备 IP 继续管理。更换网络后约 1.5 秒再切换连接，让保存响应先返回。

热点最多开放 10 分钟，连续联网 60 秒后提前关闭。持续离线 30 秒会开放一轮恢复热点，过期后可重启或长按 GPIO3 再开放。网页资源全部内置，无外部字体、脚本或 CDN 依赖。

以下内容写入 ESP32 NVS，断电保留：

| 配置 | 保存内容 |
| --- | --- |
| 网络与显示 | Wi-Fi 名称与密码、时区、NTP、常态亮度、自动休眠时间 |
| 管理登录 | 设备生成的 `KEY`，普通重启不改变 |
| 内容轮播 | 显示项目与统一停留时间 |
| MQTT | 开关、服务器、端口、TLS、主题、ClientID、用户名与密码 |
| 心知天气 | 开关、查询位置、公私钥与刷新间隔 |

配置使用版本化记录和 CRC32，校验或写入失败不改变运行配置。网络设置版本 2 保存休眠时间，兼容版本 1，迁移时保留网络信息并默认使用 60 分钟。温湿度、天气缓存、消息、播放进度、故障计数和亮屏计时不写入 Flash；轻睡眠保留，重启清空。

网页不回显已保存的密码和密钥，支持保留、替换、清除等明确操作。接口使用 HTTP Basic、CSRF 校验和同源策略；服务为本地 HTTP，NVS 未启用机密数据加密，适用于可信局域网。当前没有管理密码重置页面，清除 NVS 会一并删除配置。

## 硬件与构建

| 硬件 / 配置 | 默认值 |
| --- | --- |
| 开发板 | LuatOS CORE-ESP32-C3，PlatformIO `airm2m_core_esp32c3`，DIO Flash |
| VFD | M202MD28AA 改装 UART，`CLOCK_VFD_TX=GPIO0`，9600 baud / 8N1，单向输出 |
| AHT10 | 地址 `0x38`，`CLOCK_I2C_SDA=GPIO4`、`CLOCK_I2C_SCL=GPIO5` |
| 按钮 | `CLOCK_BUTTON_PIN=GPIO3`，低电平按下；设为 `-1` 禁用按钮 |
| 编译默认 Wi-Fi | `CLOCK_WIFI_SSID` / `CLOCK_WIFI_PASSWORD` 默认空，NVS 保存值优先 |
| 动画 | `CLOCK_ANIMATION_LEVEL=2`，可设 0 关闭、1 轻量、2 标准 |
| VFD 时序 | `CLOCK_VFD_STARTUP_MS=2200`、`CLOCK_VFD_WAKE_SETTLE_MS=100` |

如需覆盖编译默认值，复制 `include/local_config.example.h` 为 `include/local_config.h`。该文件已被 Git 忽略；含个人凭据的固件不应作为公共固件分发。本地原始 `network-clock.ino` 含历史账号信息，也被忽略；脱敏参考位于 `reference/`，不参与构建。

依赖固定为 `espressif32@8.0.0`、Arduino-ESP32 3.3.12、arduino-mqtt 2.5.3。默认环境适用于外置 USB-UART 连接 UART0 的板型：

```sh
pio run -e esp32c3
pio run -e esp32c3 -t upload --upload-port /dev/cu.YOUR_SERIAL_PORT
```

USB 直接连接 GPIO18/19 的版本使用 `pio run -e esp32c3-usb`。`esp32c3-mqtt-check` 使用虚构凭据，仅用于编译检查，不用于烧录。默认上传速率 115200，避免已遇到的高速上传校验错误。

采用 `min_spiffs.csv` 的 4MB 分区，预留双应用槽，但 **OTA 尚未实现**。首次从旧分区升级需完整串口烧录。屏幕协议依据 [M202MD28AA 手册](docs/M202MD28AA_A.pdf) 和已点亮的改装接口，不使用原厂 USB HID，不写入屏幕 FROM。

## 代码结构

- `src/main.cpp`：主循环、按键、显示、自动省电及业务调度。
- `include/clock/messages.h`：8 条消息队列、分级时长、淘汰、滚动与确认。
- `include/clock/message_payload.h`：有界 JSON 解析、正文和级别校验。
- `include/clock/pending_messages.h` / `src/mqtt_service.cpp`：4 条临时缓冲及 MQTT 工作任务；解析在锁外完成，缓冲操作在短临界区内完成。
- `include/clock/settings.h` / `src/portal.cpp`：配置校验、NVS、设备鉴权及网页 API；HTTP 服务在独立任务中运行。
- `include/clock/auto_power.h` / `manual_control.h`：省电计时、按键去抖、消息确认与唤醒按键释放保护。
- `include/clock/aht10.h` / `i2c_recovery.h`：传感器状态机与有界总线恢复。
- `src/weather_service.cpp`：独立天气任务，网络等待不阻塞显示。
- `include/clock/display_service.h` / `rotation.h`：显示与轮播状态机，动画和编码按完整字格处理。
- `web/`：网页源文件；构建时由 `scripts/embed_web.py` 生成 `include/clock/web_assets.h`，不直接编辑生成文件。

## 验证

C++17 主机测试使用 AddressSanitizer / UndefinedBehaviorSanitizer，覆盖消息级别与精确到期边界、暂停和计时回绕、满队列淘汰、严重消息保护、旧 ID 确认、传感器恢复、配置迁移和最长 9 小时休眠：

```sh
sh scripts/test.sh
```

JSON 解析使用与当前 ESP32 SDK 一致的 cJSON 1.7.19 源码测试：

```sh
sh scripts/test_message_payload.sh /path/to/cJSON-1.7.19
sh scripts/test_weather_response.sh /path/to/cJSON-1.7.19
```

网页 DOM 测试需要 jsdom 26.1.0，可安装在临时目录；不是设备的生产依赖：

```sh
npm install --prefix /tmp/vfd-clock-web-test jsdom@26.1.0
for test_file in test/web*_test.cjs; do
  NODE_PATH=/tmp/vfd-clock-web-test/node_modules node "$test_file"
done
sh scripts/preview_animation.sh
NODE_PATH=/tmp/vfd-clock-web-test/node_modules node test/animation_preview_test.cjs
```

`python3 test/web_preview.py` 可启动管理页 fixture 预览。动画预览由实际 `DisplayService` 生成，包含 10 种场景 × 3 档动效。主机与 DOM 测试不能代替实物上的按键手感、消息收发、屏幕观感、功耗及电气稳定性验收。

最近验证：默认 `esp32c3` 固件编译、完整烧录和校验通过；消息 JSON、双队列、网页及动画预览测试通过。实机运行期间未见异常重启、天气返回 HTTP 200；AHT10 当前仍报 I²C 写入失败，未恢复有效读数，需继续排查。

## 尚未实现

人体传感器和光照传感器尚未连接，人体存在判断、光敏自动亮度未实现。股票、粉丝数、自定义轮播顺序、分页面停留时间及 OTA 仍待接入；GPIO 轻睡眠和手动亮度已实现。
